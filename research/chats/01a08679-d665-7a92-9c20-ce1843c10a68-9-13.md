Yes. We can use existing data for a **simulation/dry-run layer**, even before collecting anything on a Pi.

Best candidates:

1. **Sleep-EDF Expanded**
   Public PhysioNet PSG + hypnogram data. Good for testing ingestion, sleep-stage parsing, cue-window simulation, and “what if pink-noise pulses were scheduled here?” analyses. It will not tell us the biological effect of pink noise, because no stimulus was actually delivered.
   Source: [PhysioNet Sleep-EDF Expanded](https://www.physionet.org/content/sleep-edfx/1.0.0/)

2. **NSRR datasets**
   Larger sleep data commons with polysomnography, actigraphy, questionnaires, and harmonized variables. Better for scaling the machine and testing robustness across many nights/people. Requires an NSRR account/data request for downloads.
   Sources: [NSRR overview](https://sleepdata.org/about), [NSRR datasets](https://sleepdata.org/datasets), [NSRR data commons paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC6188513/)

3. **Surrey REM closed-loop auditory stimulation dataset**
   This is closest to “real stimulation data”: high-density EEG, sleep scoring, and closed-loop auditory stimulation during REM, with alpha/theta phase targeting. It is not exactly slow-wave pink-noise memory cueing, but it is very useful for testing state-timed sound intervention logic.
   Sources: [Surrey dataset record](https://openresearch.surrey.ac.uk/esploro/outputs/dataset/Closed-loop-auditory-stimulation-targeting-alpha-and/991115569402346), [paper/PubMed](https://pubmed.ncbi.nlm.nih.gov/39208441/)

4. **Closed-loop slow-oscillation pink-noise literature**
   Some papers give enough protocol detail to simulate expected cue schedules even without raw data. Besedovsky et al. used phase-locked 50 ms pink-noise bursts during NREM slow oscillations with sham markers. Meta-analyses are useful for expected effect-size priors and falsification thresholds.
   Sources: [Besedovsky et al., 2017](https://pubmed.ncbi.nlm.nih.gov/29215045/), [Wunderlin et al., 2021 meta-analysis](https://pubmed.ncbi.nlm.nih.gov/33406249/), [Harlow et al. meta-analysis](https://pubmed.ncbi.nlm.nih.gov/41426467/)

5. **COsleep**
   More of an implementation/simulator reference than a clean scientific dataset, but useful for Raspberry Pi/OpenBCI-style architecture. It includes closed/open-loop auditory sleep stimulation concepts, logging, markers, and example data links.
   Source: [COsleep GitHub](https://github.com/Frederik-D-Weber/cosleep)

How I’d use these in Faraday:

- **Simulation 1:** Take Sleep-EDF hypnograms, synthesize sham “cue opportunities” during N2/N3 or sleep onset, and test whether Faraday can preserve timing windows, stage labels, randomization, and run receipts.
- **Simulation 2:** Recreate a pink-noise closed-loop protocol from literature as synthetic markers over real PSG, with no effect claim.
- **Simulation 3:** Use the Surrey REM CLAS dataset for a real intervention reanalysis, where stimulus markers actually exist.
- **Simulation 4:** Feed meta-analysis effect sizes into synthetic outcome generators, so the machine can practice “support / inconclusive / weakened” outcomes.

Key distinction: Sleep-EDF and NSRR can simulate the **experiment machinery**. Surrey-style CLAS data can test parts of the **intervention analysis**. Neither proves “mind control,” but they let us make Faraday/Sherlock practice the chain: source preservation → dataset manifest → protocol → synthetic/stimulus markers → analysis → bounded claim.
